# AGENTS.md

A Motoko testing library (`mo:test`) that runs unit, async, and replica tests via `mops test`.

## Build & test

This is a [Mops](https://docs.mops.one) package; there is no separate build step. Install the Mops CLI, then:

- Run all tests: `mops test` (discovers `*.test.mo` files under `test/`).
- Toolchain versions are pinned in `mops.toml` under `[toolchain]`: `moc = "1.0.0"`, `wasmtime = "40.0.0"`. CI additionally installs `dfx` `0.30.1`.

CI (`.github/workflows/pull_request_build.yml`) runs on pull requests and executes `mops test`, so changes must pass that command locally.

## Replica tests

Some tests (e.g. async/system tests) run against a local IC replica. `mops test` starts a replica on port `4945`, deploys compiled test actors, and calls their `runTests` method. A replica test file defines an unnamed `persistent actor { ... }` exposing `public func runTests() : async ()`.

## Layout

- `src/` — library source. `src/lib.mo` is the package entry point (`mo:test`); `src/async.mo` is `mo:test/async`.
- `src/expect/` — the `expect` matcher API, one file per matcher type (`expect-nat.mo`, `expect-text.mo`, etc.).
- `test/` — the library's own test suite, in `*.test.mo` files.

## Conventions

- Test files must live in `test/` and be named `*.test.mo` to be discovered.
- `.mops/` is generated by the Mops CLI (git-ignored); never hand-edit it.
- `expect.call` is only exported from `mo:test/async`, not `mo:test`.
- Update `CHANGELOG.md` and bump `version` in `mops.toml` when releasing user-facing changes.
